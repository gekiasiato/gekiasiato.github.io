# 鳥取大学 劇団あしあと ホームページ 引継ぎマニュアル

このホームページは **無料** で公開・運用できるように作っています。
パソコンに何もインストールしなくても、**ブラウザだけで更新できます**。

---

## 1. ファイルの構成

| ファイル | 内容 | ふだん触る？ |
|---|---|---|
| `content.js` | **文章・公演情報・お知らせ・写真・SNSなど全部ここ** | ★ここだけ編集 |
| `images/` | ロゴ・フライヤー・写真などの画像 | 画像を追加するとき |
| `images/ogp.png` | SNSでURLをシェアしたときに出る画像（1200×630） | 基本触らない |
| `images/favicon.png` `images/apple-touch-icon.png` | ブラウザのタブ・スマホのホーム画面のアイコン | 基本触らない |
| `index.html` | ページの骨組み（各セクションの見出しだけはここ） | 見出しを変えるとき |
| `style.css` | 色・デザイン | デザインを変えたいとき |
| `script.js` | 表示のプログラム | 触らない |
| `README.md` | このマニュアル | 引継ぎ時に追記 |

## 2. 公開のしかた（最初に1回だけ）

無料の **GitHub Pages** を使います。

1. [GitHub](https://github.com/) で劇団用のアカウントを作る（Sign up）
   - **劇団共用のメールアドレス（gekiasiato@gmail.com など）で作る**（卒業しても引き継げるように）
   - Username はURLになります（例：`gekidan-ashiato` → `https://gekidan-ashiato.github.io/`）
   - 2段階認証を求められたら設定し、**リカバリーコードを保存**しておく
2. 右上の「＋」→「New repository」
   - Repository name：**`（Username）.github.io`**（例：`gekidan-ashiato.github.io`）
     → こうするとURLが `https://gekidan-ashiato.github.io/` と短くなります
   - **Public** を選ぶ（Private だと無料で公開できません）→「Create repository」
3. 作成した画面の「**uploading an existing file**」をクリック
4. パソコンでこのフォルダを開き、次の6つを選んで**まとめてドラッグ＆ドロップ**
   - `index.html` `style.css` `script.js` `content.js` `README.md` `images`フォルダ
   - ※ `.claude` フォルダはアップしない（作成用の設定ファイルです）
   - ※ フォルダごと（「あしあとHP作成」ごと）ではなく、**中身**をドラッグする
5. アップロードが終わったら、下の「**Commit changes**」を押す
6. 「Settings」→ 左メニュー「**Pages**」
   - Source：**Deploy from a branch**
   - Branch：**main** / **/(root)** →「Save」
7. 1〜3分待ってページを再読み込みすると、上に「Your site is live at 〜」とURLが表示されます

### うまくいかないとき
| 症状 | 原因と対処 |
|---|---|
| 404 と表示される | 数分待つ／`index.html` がリポジトリの一番上にあるか確認（フォルダの中に入っていたらNG） |
| 画像が出ない | `images` フォルダがアップされているか確認 |
| 文字だけでデザインがない | `style.css` がアップされているか確認 |
| 直したのに反映されない | 数分待ってから、スマホ・PCで再読み込み |

## 2.5 公開前に団員で確認する（確認モード）

`content.js` の一番上にある `previewMode` で切り替えます。

| 設定 | 状態 |
|---|---|
| `previewMode: true,` | **確認モード**。ページ上部に黄色い帯で「公開前の確認用ページです」と表示され、Google などの検索結果に出ないようにします |
| `previewMode: false,` | **本公開**。帯が消え、検索結果にも出るようになります |

### 手順
1. `previewMode: true,` のまま、上の「2. 公開のしかた」でGitHub Pagesにアップする
2. 表示されたURLを**団員のLINEグループだけ**に共有して確認してもらう（下の依頼文をコピーして使えます）
3. 出てきた修正点を `content.js` に反映する
4. OKが出たら `previewMode: false,` に変えて保存 → これで本公開
5. Instagram・X のプロフィールにURLを載せて告知

> ※ 確認モード中も、URLを知っている人は見られます。URLは団員以外に広めないでください。

### 団員への確認依頼文（例）
```
【HP確認のお願い】
劇団あしあとのホームページを作りました！公開前に確認をお願いします🙏
（まだ公開前なので、URLは劇団外に共有しないでください）

URL：https://gekiasiato.github.io/

▼見てほしいところ
・誤字脱字、情報のまちがい（公演日時・会場・SNSなど）
・スマホで見て、読みにくい／押しにくいところ
・予約フォームやSNSのリンクがちゃんと開くか
・載せたほうがいいこと、載せないほうがいいこと

〇月〇日までに、このグループか個人LINEで教えてください！
```

## 3. 文章の更新のしかた（ブラウザだけでOK）

1. GitHub にログインし、リポジトリを開く
2. `content.js` をクリック → 右上の **鉛筆マーク（Edit）** をクリック
3. 書き換える
4. 右上の「**Commit changes...**」→ もう一度「Commit changes」
5. 1〜2分でホームページに反映されます

### よくある更新

- **お知らせを追加**：`news:` の中の一番上に、1行コピーして貼り付けて書き換える
  ```js
  { date: "2027.04.01", category: "募集", text: "新歓公演を行います！" },
  ```
- **次回公演を変更**：`nextStage:` の中身を書き換える
  - 公演予定がないとき → `show: false`
  - 予約フォーム（Googleフォームなど）ができたら → `reserveUrl: "https://..."`
- **公演が終わったら**：`pastStages:` の一番上にその公演を追加（空のあいだは「過去の公演」の見出しごと隠れます）
- **入団の申し込みフォームができたら**：`join:` の `formUrl:` にURLを貼る
  - フォームのボタンとInstagram DMのボタンが並びます
  - 使わない方は URL を `""` にすると消えます

### 書き方の注意

- 文字は `" "` で囲む、行末に `,` を付ける
- 改行したいところは `<br>`
- スマホで変なところで改行されるときは、折り返してよい位置に `<wbr>` を入れる
  ```js
  title: "『アンフォ<wbr>ゲッタブル』",
  ```
- 言葉づかいは **団員／団費／入団／掛け持ち**、「あしあと」はひらがなでそろえる
- **保存後にページが真っ白／赤い警告が出たら**、カンマか `"` の付け忘れです
  → GitHub の「History」から前のバージョンに戻せるので安心してください

## 4. 画像（フライヤー・写真）の追加

1. リポジトリで `images` フォルダを開く
2. 「Add file」→「Upload files」→ 画像をドラッグ →「Commit changes」
3. `content.js` の該当する場所にファイル名を書く

| 書く場所（content.js） | 表示される場所 |
|---|---|
| `nextStage:` の `flyer:` / `flyerBack:` | 次回公演のフライヤー（表・裏） |
| `heroPhoto:` | トップの大きな写真（空ならロゴ） |
| `about:` の `photo:` / `photoCaption:` | 「劇団について」の写真と説明 |
| `pastStages:` の各公演の `photo:` | 過去の公演一覧の小さな写真 |

```js
heroPhoto: "top-2027.jpg",
```
- ファイル名は **半角英数字** にしてください（日本語名だと表示されないことがあります）
- 画像は 1MB 以下くらいに縮小しておくと表示が速くなります
- **人が写っている写真は、写っている本人の許可を取ってから**載せてください

## 4.5 大きな変更は「ブランチ」と「プルリクエスト」で

`main` はそのまま公開ページにつながっています。お知らせ1件などの小さな更新は `main` で直接編集してOKですが、
**デザインや複数ファイルにまたがる変更**は、次の手順で「下書き用の枝（ブランチ）」に入れてから反映します。

1. リポジトリのトップで、左上の「**main ▼**」を押す → 新しいブランチ名（例：`improve-2026-11`）を入力 →「**Create branch …**」
2. 「main ▼」の表示が新しいブランチ名に変わっていることを確認
3. 「Add file」→「Upload files」で、変更したファイルをドラッグ（`images` はフォルダごと）
4. 下の「Commit changes」を押す（**「Commit directly to the 〇〇 branch」**になっていることを確認）
5. 上に出る「**Compare & pull request**」を押す → 内容を書いて「**Create pull request**」
6. 「Files changed」タブで変更点を確認し、問題なければ「**Merge pull request**」→「Confirm merge」
7. 1〜3分で公開ページに反映されます

> マージするまでは公開ページは変わりません。やめたいときはプルリクエストを「Close」すればOKです。

> ⚠️ **`style.css` や `script.js` を変えたときは、`index.html` の `?v=20261124` （3か所）を新しい日付に書き換えて一緒にアップしてください。**
> これを忘れると、見る人のブラウザに古いデザインが残り、メニューの文字がくっつくなど表示が崩れて見えることがあります。
> （`content.js` だけの更新なら不要です。反映まで最大10分ほどかかることがあります）

## 5. 引継ぎのときにやること

- [ ] GitHub アカウントのログイン情報（メールアドレス・パスワード）を**口頭や紙など安全な方法で**次の担当者へ渡す
  - 2段階認証を設定している場合は、認証の端末・リカバリーコードも引き継ぐ
- [ ] 次の担当者と一緒に「お知らせ」を1件更新してみる
- [ ] SNSのURL・メールアドレスが変わっていたら `content.js` の `contact:` を更新
- [ ] この README に、気づいたことや注意点を追記する

> 💡 より安全にしたい場合：GitHub の「Organization（無料）」を劇団名で作り、
> 歴代の担当者を「メンバー」として招待する方法もあります。
> パスワードを渡さなくても、各自のアカウントで編集できるようになります。
